## 文件

- `MATERIALS_50.md`：阅读版，含全部50条正文、回复关系与来源链接。
- `EngageMessages_synthetic_50.csv`：仅50条新增模拟消息。

## 合并与来源规则

保留原23个导出字段，增加 `DataOrigin`、`IsSynthetic`、`ScenarioId`、`SourceRefs` 四个来源字段。原有12条的原字段逐项保持不变。原有数据按仓库说明包含11条测试帖和1条真实观点帖；`IsSynthetic=False`仅表示不是本次生成，不能将这12条都解释成自然业务活动或已核实事实。

新增作者均为占位身份，ID与既有样例不冲突。时间是模拟排序时间；`.invalid` URL只用于结构验证，不能打开原帖。SourceRefs映射见阅读版末尾。没有导入真实内部文档，也没有获取新的SharePoint数据。

素材覆盖需求检索、摘要忠实性、本地推理、跨语言、制造质量、ECU测试、售后、能耗、供应商文档及培训反馈。特别保留短而有用的回答、长空话、错误结论及纠正、重复帖子、提示指令干扰、计划/完成状态等例子。S39含故意错误结论，S40是纠正；S44含测试指令，只作为待分析正文。

## 用于当前本地验证

在项目根目录运行：

```powershell
python tools/build_forvia_materials.py
python -m poc.run_poc examples/forvia_materials/EngageMessages_merged_62.csv
```

POC写入已有 `poc_output/` 目录，可能覆盖同名演示输出。生成脚本只写本子目录中的生成文件，不修改源样例。修改素材后重新生成即可。

当前POC读取已定义字段；新增来源字段和设计标签不参与模型输入。后续接入模型时继续排除这些辅助字段，避免标签泄漏。汇总时应保留MessageKey并关联来源字段，将原有样例和新增模拟数据分开报告。

数据生成与结构检查已通过：50条新增、62条合并、MessageKey唯一、原23字段保持、父帖及线程引用完整。后续评分任务已在项目 `.venv` 中安装依赖并完成62条端到端试评分，结果见 `../quant_validation/` 和项目根目录 `PART2_SCORECARD_VALIDATION.md`。使用 `.venv/Scripts/python.exe` 运行；系统默认Python可能仍缺少jieba。候选分仅供探索，当前全部待复核。

建议先由两位评阅者独立看正文与父帖，标注类型、证据片段、评分和需复核理由，再查看作者设计标签讨论分歧。不要把作者标签或当前规则输出当成人工答案。这批数据适合流程与边界测试，不能证明真实论坛分布、员工表现、模型准确率或统计显著性。不要把同一讨论串、重复对或改写对随机拆到训练与测试两侧。

50条模拟内容也不是50次真实业务实验。文内练习数字、成绩和经历均为虚构；公司公开背景与论文链接是真实引用。未向SharePoint或Viva Engage发布帖子或积分。
